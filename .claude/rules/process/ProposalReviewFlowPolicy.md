## Lifecycle (authoritative flat state table, CRP-261)

| state | actions | next |
|:---|:---|:---|
| `suggested` | edit, do, hold, withdraw, supersede | in_progress, held, withdrawn, superseded |
| `in_progress` | edit, verify, hold, reset, withdraw, supersede | verified, held, suggested, withdrawn, superseded |
| `verified` | bcr, reopen, hold, supersede | in_review, in_progress, held, superseded |
| `in_review` | complete, commit, reject, reopen, hold | completed, rejected, in_progress, held |
| `completed` | push, hold, reinstate | pushed, held, revision |
| `held` | continue, edit, withdraw | recorded `resume_state`, withdrawn |
| `pushed` | view, reinstate | revision |
| `withdrawn`, `rejected`, `superseded` | view | terminal |

- Legacy terms (`Scoped`, `Decided`, `Approved`, `Committed`, `Published`, `processed`, `deferred`, `Cancelled`) are compatibility vocabulary only; they MUST NOT define a second lifecycle; the 7 legacy Sync Points are a historical lineage mapping only.
- `state` + `state_reason` is the single current record; history is append-only. Held without history resumes to `suggested`. Direct Gate 2 acceptance from `in_progress`/`verified` auto-promotes through `verified` -> `in_review`.
- `reinstate <CRP>`: without `-Changes` -> `suggested`; with `-Changes` -> `in_progress`, then verified + exact-identity BCR; never complete a stale BCR.

## Rules

- **RULE-LCM-001** In LCM mode every idea/question is a proposal (`suggested`) only; no immediate file changes or commits. Register conclusive paths as `suggested` in the authoritative ledger `LCM_Inventory/data/proposals/proposals.db` via governed tools (`Update-Proposal.ps1`, `Invoke-ProposalAction.ps1`, `Sync-LcmProposalsDb.ps1`); `proposals.json` is a transition fallback only. Structural proposals/BUGs need the Gate 0 Contract before the planning boundary. [Claude] `proposals.sql` is dumped at push, not synchronous; Claude never edits the ledger by hand.
- **RULE-LCM-002** Automatic BCR at every CRP/COH review gate for the exact resolved target; no completion without a matching BCR disposition (only exception: recorded authorized bypass; `-Force`/`-Immediately` are not bypasses). Cohort: sync all members to the gate state first, fail closed per member, one BCR for the whole COH. Target is one explicit Item (`CRP` incl. BUG, or `COH-<prime>`), no fallback to repo/row/selection. At most one open COH; open = atomic close-current/open-selected; all-or-nothing membership. `DOIT` may cross Gate 1, NEVER Gate 2. Commands: `Proceed` (one state step), `do` (sets DOIT), `hold`, `continue` (alias `resume`), `COMPLETE` (-> `completed`, local commit, never push), `PUBLISH`/`PUSH` (`completed` -> `pushed`, lockstep), `withdraw` (alias `cancel`; Gate 1, -> `withdrawn`, zero reverts, switches OFF), `reject` (Gate 2, -> `rejected`, rollback to pre-CRP baseline, switches OFF), `give open Proposals`, `give repos under review`.
- **RULE-LCM-003** `review_granularity`: `tight` (default, stop per proposal; every push resets to `tight`, RULE-DEC-005.4) or `coarse` (one BC5 stop per batch); never open a duplicate review window, refresh in place.
- **RULE-LCM-004** Every governed repo and the root container get visual diff review via `BCR.cmd` / `Invoke-MacriumBcrReview.ps1` before commit (exceptions per RULE-REV-001). Single-session junction review (`FollowSymLinks`). `LCM_Inventory` `data/`, `logs/`, `scratch/` evidence is exempt (peek allowed, advisory only); `tools/`, `modules/`, `docs/`, `tests/`, `Cmd/` require review.
- **RULE-LCM-005** After an accepted target-repo commit, update and commit `LCM_Inventory` immediately; every PUSH runs a non-mutating lockstep preflight, failure blocks the cohort; cohort bundles coordinate but do not replace member histories.
- **RULE-LCM-006** `LCM OFF` (emergency escape, back via `LCM ON`/`resume LCM`); `Testing OFF` (defer deep tests to pre-push; syntax and fast checks still run; deferred failure aborts push and spawns a BUG in DOIT); every push resets LCM Mode and Testing Mode to ON.
- **RULE-LCM-007** Single-dimensional status bound to the flat states `suggested` -> `in_progress` -> `verified` -> `in_review` -> `completed` -> `pushed` (exceptional/terminal: `held`, `withdrawn`, `rejected`, `superseded`); dispositions are markers, not states: `BUG` (sets DOIT, halts at Gate 2), `held` (pauses switches, cleared by `continue`), `approved` (Gate 1 / Gate 2 acceptance). Flow switches: `-DOIT`, `-Force` (Gate 2 emergency only, RULE-REV-001), `-Immediately` (BUG recovery cohort, recorded reason, ends at Gate 2), `-MinimalTests`, `-Coarse`/`-Tight`, `LCM OFF`, `Testing OFF`, `ADMINMODE` (per-tool elevation design criterion). Plans/walkthroughs archived in the bundle (`LCM_Inventory/docs/Proposals/CRP-<nnn>-<Slug>/Implementation_Plan.md`, `Walkthrough.md`) and linked as `plan_path` / `walkthrough_path` in `proposals.db`.
- **RULE-LCM-008** `BUG` -> DOIT: scaffold `BUG-<nnn>-<Slug>/`, implement and verify without Gate 1 pause, halt at Gate 2 on `verified` (`BCR.cmd` / `Invoke-MacriumBcrReview.ps1`, await disposition). Gate 2 bypass only by explicit `IMMEDIATELY`/`FORCE` or critical loop within the 2-attempt breaker; log justification in bundle and ledger.
- **RULE-LCM-009** CRP bundle `docs/Proposals/CRP-<nnn>-<Slug>/` with `Specification.md`, `Implementation_Plan.md`, `Walkthrough.md`; `nnn` = ledger id, zero-padded >= 3; metadata per RULE-LCM-012.3: `CRP-ID`, `Title`, `Scope`, `Version`, `Affected-Repos`, `Status`, `Priority` (0-10), `App-ID`; legacy flat files valid (LCM-020 Mode 3).
- **RULE-LCM-010** A self-discovered bug in a permanent tool/script/module/UI MUST be registered as a BUG in `proposals.db` (governed tools) with bundle and fixed in DOIT (Gate 2 still binding); no silent hotfixes.
- **RULE-LCM-011** BUG bundle `docs/Proposals/BUG-<nnn>-<Slug>/` (shared counter); frontmatter Bug-ID, Scope, Version, Affected-Repos, Severity, Status, Root-Cause.
- **RULE-LCM-012** Every non-bug feature/tool/workflow/policy proposal needs a standalone `Specification.md` in `LCM_Inventory/docs/Proposals/` linked by `bundle_id`. Missing spec or YAML fence MUST NOT fail transitions: `ProposalSpecificationState.psm1` scaffolds and injects/extends the YAML block (`CRP-ID`, `Title`, `Scope`, `Status`, `Plan-State`, `Progress-State`, `Priority`, `App-ID`); unresolvable conflicts halt for operator triage.
- **RULE-LCM-013** Every PUSH runs `Update-Gemini.ps1` first (rules export, 21 files, `D:\GDrive\LCM` mirror), commits export changes, then pushes; direct `git push` bypassing `Invoke-LCM_Push.ps1` is prohibited. [Claude] Claude pushes only via `PUBLISH` / `Invoke-LCM_Push.ps1`, never raw `git push` (hook candidate).
- **RULE-LCM-014** CRPs are born `suggested`; at Gate 1 scaffold bundle, register, present plan, then UNCONDITIONALLY HALT: no source/script/config/test change unless `IMMEDIATELY`/`FORCE`. `Proceed` -> `in_progress` (interactive checkpoints); `do` -> `in_progress` + DOIT. Gate 2 (BC5) is mandatory except RULE-REV-001. `Specification.md` is the only document requiring formal acceptance; ledger records accepting operator, timestamp, path, scope. [Claude] Gate 1 halt = remain in plan mode / end turn.
- **RULE-LCM-015** Intake: `CRP:` -> `suggested`, halt at Gate 1; `BUG:` -> DOIT to Gate 2. Priority 0..10 orders batches, never bypasses Gate 2.
- **RULE-LCM-016** `Proceed` = exactly one state step (Gate 1 `suggested` -> `in_progress`; review decision `in_review` -> `completed` with disposition, SemVer increment, local commit); `do` = DOIT to Gate 2; `COMPLETE <CRP|BUG|repo|cohort>` / `COMPLETE ALL` = review completion + local commit, list changed files and scope amendments first, never push; `PUSH` = completed cohort with `LCM_Inventory`, any missing/remote-less/not-ahead member blocks all, resets modes to ON.
- **RULE-LCM-017** Implicit PROCEED only for a critical system/transport BUG that is within capability, needs no redesign, and has net positive impact. 2-attempt loop breaker: after two failed attempts HALT, report raw evidence, mark the item, yield; no cascading speculative launch mechanisms.
- **RULE-LCM-018** Segment batches to avoid credit/context exhaustion; each item reaches a stable verifiable state before the next.
- **RULE-LCM-019** `Workon: A<#>` sets inherited `app_id`; `Workon: Architecture`/`Base` clears it. `COMPLETE` synthesizes decisions into `Architecture.md`/`Requirements.md`/`Implementation.md` under `## App: #`.
