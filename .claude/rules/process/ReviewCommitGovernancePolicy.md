- **RULE-REV-001** Every commit of code, config, tools, modules, structural assets or docs in a governed repo needs a prior validated review disposition (`completed` / `completed_with_edits`) from the BC5 visual review gate (`BCR.cmd` / `Invoke-MacriumBcrReview.ps1`, FollowSymLinks); BUGs in DOIT halt before `completed`. Gate 2 is non-circumventable by default, also for BUGs in DOIT. Two exceptions: (1) explicit operator `IMMEDIATELY` / `FORCE`; (2) critical flow-impeding BUG/loop, `-MinimalTests`, at most 2 attempts. Both MUST be logged in the bundle and CM ledger. An exception waives only visual inspection, never syntax, language rules or `Test-RepoReadiness.ps1`. RULE-EFF-001 artifacts are exempt (peek advisory). BCompare decides materiality; left pane read-only baseline; live-pane edits = "accepted with changes"; raw-byte/Git/EOL/whitespace diffs never create review candidates. Headless fallback: unified console diff + `Walkthrough.md` evidence for terminal disposition. [Claude] Claude commits and pushes only through the governed tools (`COMPLETE` / `Submit-ReviewResult.ps1`, `PUBLISH` / `Invoke-LCM_Push.ps1`), never raw `git commit` / `git push` (hook candidate).
- **RULE-REV-002** `Completed with Edits` MUST pass `Test-RepoReadiness.ps1`, introduce no violations, then counts as `completed`; under `-MinimalTests` recorded as `completed` with `test_scope: minimal`.
- **RULE-REV-003** `rejected` / `held`: pipelines halt; commit/push only with explicit forced override.
- **RULE-REV-004** RULE-REV-001..003 override any general "all commands permitted" or background execution policy. [Claude] Includes Claude permission allowlists.
- **RULE-REV-005** Each disposition (`completed`, `completed_with_edits`, `rejected`, `held`) is recorded (timestamp, reviewer, HEAD SHA, notes) in `LCM_Inventory/logs/cm_activity.log`, `LCM_Inventory/data/reviews/REVIEW-<Repo>-<Timestamp>.json`, the CR record (`LCM_Inventory/data/change_requests.json`) and, for structural changes, against the Gate 0 exit criteria.
- **RULE-REV-006** On reaching Gate 2: launch `BCR.cmd` / `Invoke-MacriumBcrReview.ps1` and immediately end the turn with no further tool calls. `Proceed` at Gate 2 = one step `in_review` -> `completed` + local commit with SemVer per REV-007. `PUSH` is the only remote push; `completed` cohort with `LCM_Inventory`; resets LCM/Testing Mode to ON.
- **RULE-REV-007** Every committed change increments the repository version: Major `+1.0.0` (resets minor and patch to 0 for all components, e.g. 10.2.5 -> 11.0.0; RULE-DOC-005); Minor `+0.1.0` at release (does not reset patch); Patch `+0.0.1` on commit only for physically changed components. Update DOX headers, tripartite specs, README/manifests, `inventory.json`; record the version in commit message and receipt. Routine `LCM_Inventory` data/log/dashboard/review accounting (incl. `proposals.db`) does not bump `LCM_Inventory`.
- **RULE-REV-008** BC5 sessions use `<FollowSymLinks Value="True"/>`; single window, no dual sessions; baseline hierarchy: primary = BCR, live `D:\Git_Repositories` vs mounted Macrium image `<MountedDrive>:\Git_Repositories` with the `_LCM` profile (RULE-REV-014); fallback only where Macrium is unavailable (headless, REV-001.6) = left pane exported from the explicit local `BaseCommit` (no remote substitution); junction paths replaced by a committed rules snapshot chosen in the stated order and recorded (source repo, path, SHA, selection source); live-only files appear as additions; cache identity and pane title show target SHA and rules SHA; filters MUST NOT exclude `.agents\rules\`.
- **RULE-REV-009** If a finding changes the durable review contract: tell the operator before claiming completion (separate code change from pending governance change); update this policy in the same change set; sync `AGENTS.md` and the cross-reference (RULE-AUTH-002).
- **RULE-REV-010** No Gate 2 review or commit gating without prior mechanical parsing (per INVARIANT-RULES syntax gate, incl. Go) and unit tests recorded in `Walkthrough.md`.
- **RULE-REV-011** Rule changes require `ADMINMODE = true` (member of SID `S-1-5-32-544`, independent of elevation); hidden state; `Make-Admin -Mode On|Off` for eligible users only; non-admin attempts audited; review submission enforces ADMINMODE for staged rule paths and logs user, SID, CRP, paths.
- **RULE-REV-012** Review launchers MUST NOT kill or force-single operator BC windows or poll titles intrusively; MUST NOT silently reuse an older mounted baseline when a newer completed `.mrimgx` exists today on `B:\Backups\` (remount, or notify date/file/drive); never relaunch BC or remount unless the image changed (preserves LHS markers and sandbox state).
- **RULE-REV-013** Before dismounting a baseline drive (F:..I:) check mounted repos for modifications/markers; if found, interactive `[Y]/[N]` choice, non-interactive fail closed unless `-Force`/`-DiscardChanges`.
- **RULE-REV-014** Ad-hoc `BCompare.exe`, custom diff scripts, Git-based or single-repo comparisons are PROHIBITED; the only valid comparison is `BCR` (`BCR.cmd` / `Invoke-MacriumBcrReview.ps1` / `Invoke-MacriumDailyBcrBaseline.ps1`) at workspace root with the `_LCM` profile; if today's backup is not mounted, run BCR to mount or halt. [Claude] Claude never composes a BCompare command line.
